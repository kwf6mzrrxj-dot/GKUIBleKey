# 实时活动（Live Activity）

锁屏卡 / 灵动岛 / CarPlay 三套画布，共用一份 `ContentState`。

> **它不只是 UI**：iOS 26 起，App 有 `CBManager` 实例并启动 Live Activity 后，
> 后台可获得与前台相同的 BLE 权限（`AllowDuplicates` 继续生效）。
> 没有它，后台广播会被系统合并成十几秒一次，预认证的 29 秒节奏必然跑不准。
> 详见 `VehicleActivityAttributes` 头注释。

## 一、三套画布

| 画布 | 由谁渲染 | 内容 |
|---|---|---|
| 锁屏 / 通知中心 | `LockScreenView`（`.small`） | 车名 + 来源 + 锁态 + 时间 + 四格 |
| CarPlay | 同一个 View（`.medium`） | 同上，字号 ×1.45 |
| 灵动岛展开 | `DynamicIslandExpandedRegion` | 车名 / 锁态+时间 / 四格 |
| 灵动岛紧凑 | `compactLeading` + `compactTrailing` | 钥匙图标 + 锁态 |
| 灵动岛最小 | `minimal` | 仅图标 |

灵动岛展开态的四格与锁屏**必须给出同一组结论** —— 长按展开后信息比锁屏更少，
会让人以为锁屏那版是错的。所以判定逻辑提取成文件级的 `StatGrid`，
两处共用，而不是各写一遍。

## 二、四格为什么是「门 / 窗 / 后箱 / 引擎」

2026-11-07 把原来的「电源」换掉了。

这张卡绝大多数时候是**站在车外**看的。那一刻：

- 「窗关没关」→ 决定要不要回去关，**原来完全没显示**
- 「电源通没通」→ ACC / 点火档只有坐在车里才有意义

`VehicleSnapshot.isWindowsClosed` 一直有值（蓝牙源时由 `snapshotFromBluetooth`
从云端补），只是从没传进卡片。这次补上了。

## 三、颜色语气：不能用一条通用规则

原来的规则是 `value == true ? 白 : 橙`。对门 / 后箱成立（关着常态、开着留意），
**但套到引擎上就反了**：停着显示橙色警示、转着显示白色。

车停着是常态，不该报警；引擎在转（远程启动中 / 车正在被使用）才值得留意。

所以改成由每个字段自己声明「哪个方向算异常」，`StatTone` 三档：

| 语气 | 颜色 | 用于 |
|---|---|---|
| `.normal` | 白 | 门关 / 窗关 / 后箱关 / 引擎停 |
| `.alert` | 橙 | 门开 / 窗开 / 天窗开 / 后箱开 / 引擎转 |
| `.unknown` | 白 35% | 没上报过，显示「—」 |

**没有一个通用规则能同时对上这四项** —— 每个字段的「异常方向」不一样。

## 四、门：能说出「哪一扇」

`doorClosed: [Bool]?`（左前/右前/左后/右后）传进卡片后：

| 情况 | 显示 |
|---|---|
| 四门全关 | 关 |
| 只有左后开 | **左后** |
| 两扇以上开 | 2门开 |
| 无逐门数据 | 退回聚合值「开 / 关」 |

「有门开着」和「左后门开着」是两个量级的信息 —— 前者要绕车检查一圈，
后者直接走过去关。

## 五、窗：车窗与天窗合并，但分开表达

| 情况 | 显示 |
|---|---|
| 车窗开 | 开 |
| 只有天窗开 | 天 |
| 都关 | 关 |
| 车窗未知、天窗没开 | — |

**天窗未知时以车窗为准显示「关」，不因为天窗不确定就报「—」。**
两条理由：没有天窗的车型该字段可能恒缺，要求"天窗已知才敢说关"会让这类车
永远显示「—」，把一个能确定的答案变成不知道；且车窗才是进水的常见来源。

## 六、时间只说一次

原来「蓝牙 · 19:28」（`statusText`）和右边的相对时间（`lastReportedAt`）
说的是同一件事 —— 最后一次收到广播。锁屏上并列两个时间，
用户得先判断哪个是哪个才能回答"这数据新不新"。

现在 `statusText` 只说来源（`StatusSource.label`：蓝牙实时 / 云端 / 暂无数据），
时间统一由 `lastReportedAt` 以相对形式表达 ——「3 分钟前」比「19:28」直接。

## 七、`staleDate` 是安全兜底

之前传 `nil`：App 被系统杀掉后没有任何代码在更新卡片，
系统也不会把它标成过期 —— 锁屏上一直挂着一份**看起来是实时的旧状态**。
用户据此判断"车锁着"然后走开，比没有卡片更危险。

现在给 300 秒。比 `VehicleSnapshot.staleSeconds`（180 s）宽一档，
因为卡片更新有 2 秒节流、后台唤醒也可能晚几十秒，180 会在正常使用中误报。

只要 App 活着，每次 `update` 都把 staleDate 往后推，正常使用中不会触发。

就是照着这次修的 bug 写的断言。

## 九、已知边界

1. **没显示油量**。CarPlay 画布更宽，理论上放得下，但目前 medium 只是等比放大，
   加第六项会挤掉门窗。等真的给 CarPlay 做横向布局时再考虑。
2. **`isAccOn` / `isIgnitionOn` 不再显示**，字段保留 —— 留给将来 CarPlay 单独排版。
3. **位置没进卡片**。状态页有地图卡，实时活动里放坐标没有操作价值
   （点不进地图，也不该在锁屏暴露停车位置）。
