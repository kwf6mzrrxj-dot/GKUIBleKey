## 二、三个结构性约束（决定了什么能做、什么做不了）

1. **没有后台服务端**。所有远程能力都压在云端轮询（90 秒）+ 本地 BLE 上。
   → 做不了推送通知、多用户共享、行程统计、真实时车况。
   → 但**能做**本地通知（基于 BLE 事件 + 前台状态检查）和**云端定时任务**（车端自己执行，不需要 App 在线）。

2. **车端 BLE 命令集固定**。`IBCommandType` 只有 1–6 与 0x0D/0x11/0x12/0x55，没有座椅加热、方向盘加热、充电口。
   → 这些功能不是"没做"，是**车端协议里没有**。除非逆向新命令，否则不做。

3. **免费开发者账号**。watchOS 能装但证书 7 天一换，推送证书、App Group 之外的能力受限。
   → 方案里所有能力必须**不依赖推送证书 / 不依赖服务端**。

## 三、方案

### P0 · 安全与可信（建议本周做，约 2 天）

#### P0-1 手机端二次认证

- **问题**：现在"手机在手上 = 车能开走"。手机借人、丢失、被抢，车就是对方的。手表端已经有 `LAContext`，手机端反而没有——安全等级倒挂。
- **做法**：在 `AppModel.perform(_:)` 的统一闸门前加一层 `requireOwnerAuthentication(for:)`：
  - 需要认证的动作：解锁、后备箱、开窗、引擎启动、空调
  - 不需要：闭锁、关窗、寻车（都是"更安全"方向的动作）
  - 认证成功后 3 分钟内免重复（`evaluatedPolicyDomainState` + 时间戳），避免连点两次弹两次
  - 失败/取消 → 走现有 `resolveIntent(false)`，Siri / 控件也能正确收口
- **成本**：S（~150 行，参考 `WatchCloudController.requireOwnerAuthentication`）
- **风险**：控制中心 / Siri 场景下弹 Face ID 会打断——所以**只在 App 内前台触发**，后台 Intent 不放（否则控件永远用不了）。这是个必须写清的取舍。

#### P0-2 防误触

- **问题**：后备箱按钮误触 = 后备箱在商场停车场敞开一小时。开窗同理。
- **做法**：`secondaryAction` 增加"长按 0.6 秒"变体，用于后备箱 / 开窗 / 寻车；主键（解锁/闭锁）保持单击。长按期间按钮有进度环，松手取消。
- **成本**：S（~80 行，`LongPressGesture` + 进度动画）
- **风险**：长按在车载支架上单手操作略别扭 → 给设置项"关闭长按保护"。

#### P0-3 本地通知（车没锁 / 窗没关 / 蓝牙断开）

- **问题**：这是车控 App 被抱怨最多的一类——"我到底锁了没有"。现在只有打开 App 才知道。
- **做法**：`UNUserNotificationCenter` + 三种触发：
  1. **蓝牙断开瞬间**：如果最后已知状态是"未锁"或"有门/窗开着" → 立即本地通知「车辆未锁，点击查看」
  2. **离开 5 分钟后复查**：BLE 断开后延迟 5 分钟，若期间没有任何车辆广播 → 提示"已离开车辆，最后状态：未锁"
  3. **前台回连**：连上时如果状态从"未锁"变"已锁"以外的情况，不提示（避免噪音）
- **成本**：M（~200 行 + 权限申请 + 通知分类点击跳转）
- **风险**：通知过多会被关掉 → 只做"未锁"这一种，且每天最多 3 条。

#### P0-4 状态过期时的执行拦截

- **问题**：云端状态 180 秒窗口，超过就是"三分钟前的车况"。现在只在按钮上不推荐，但仍然允许直接执行。
- **做法**：状态超过 `cloudWindow` 时，点主键先弹一次「当前状态是 4 分钟前的，仍要解锁？」（可勾选"不再提示"）。
- **成本**：XS（~40 行，复用 `pendingExternalAction` 的确认弹窗）
- **风险**：多一次点击，但只在状态确实过期时出现。

### P1 · 主动能力与生态入口（建议两周内，约 5 天）

#### P1-1 定时任务（协议已支持，白捡）

- **价值**：冬天早上 7:30 提前开空调 / 下班前关窗。这是**真远程**能力——车端到点自己执行，不需要 App 在线。
- **做法**：`plan(for:)` 里 `scheduledTime` 从固定 `$NOW` 改成可选参数；`GKCloudClient` 增加 `schedule(_ command:at:)`。UI 放在车控页空调卡片下的「定时」入口。
- **成本**：M（~250 行：参数透传 + 时间选择 UI + 任务列表 + 取消）
- **风险**：云端定时任务的**取消接口未知**（需要抓包确认）。如果只能创建不能取消，就退化成"一次性任务，过期自动失效"，并把文案写清楚。

#### P1-2 桌面小组件 + 锁屏小组件

- **价值**：车控 App 最高频的入口其实不是 App 本身，是桌面。现在只有控制中心控件（要下拉才能看到）。
- **做法**：新增 `StaticConfiguration` 小组件，`systemSmall` 显示锁/门/电量状态 + 一个主按钮；`systemMedium` 显示状态 + 解锁/闭锁两个按钮。锁屏 `accessoryCircular` 只显示锁状态。
- **成本**：M（~300 行，复用 `QuickControlIntent` + `CloudSnapshotPayload` 的缓存）
- **风险**：小组件不能主动拉取（只能靠 Timeline 刷新），状态会滞后 → 显示"最后更新 HH:mm"，不做实时承诺。

#### P1-3 操作历史

- **价值**：车借给朋友后想确认"他到底开没开车门"；远程启动失败想回看原因。
- **做法**：本地 JSON（`Documents/action-history.json`），环形 100 条，字段：时间 / 动作 / 通道（蓝牙/云端）/ 结果 / 失败原因。入口放在「我的 → 设置 → 操作历史」。
- **成本**：S（~150 行，复用 `measured.lastSucceededAction` 的落点）
- **风险**：涉及隐私，导出时提示。

#### P1-4 一键场景

- **价值**：接孩子 = 解锁 + 开空调 24℃ + 寻车；洗车 = 开窗 + 关空调 + 解锁。
- **做法**：设置页定义 2–3 个场景，每个场景是 `[VehicleCommand]` 串行队列，间隔 2 秒。复用 `perform` 的排队机制。
- **成本**：M（~200 行 + 需要处理"中途失败是否继续"）
- **风险**：**与 29 秒被动启动节流冲突**——连续命令可能被 `timeBetweenPassiveStart` 拦。必须先验证车端能否接受 2 秒间隔的连续命令，否则这个功能做出来是半残的。

## 四、明确不做（以及为什么）

| 不做 | 原因 |
|---|---|
| 地理围栏自动解锁 | 与现有 RSSI 靠近解锁**功能重复**，且更危险：GPS 精度 10–50 米，室内/地下车库直接失效。RSSI 至少反映"真的在车边"。 |
| 远程共享钥匙 / 临时授权 | 需要服务端签发凭证 + 车端授权模型支持。协议里配对必须物理在场（0x55 + 车身动作），做不了真远程。 |
| 行程统计 / 油耗分析 | 需要持续后台拉取云端数据，免费账号 + 无服务端的情况下既不准也耗电。 |
| 离线命令队列 | "没网时点解锁，联网后自动执行"——延迟执行对车门来说是不可接受的行为。 |
| 座椅加热 / 方向盘加热 | 车端 BLE 命令集里没有，云端 serviceId 也没有对应项。不是没做，是做不到。 |

### 真机必须确认的 3 件事

1. **定时任务是否真的被服务端接受**。抓包只验证过 `scheduledTime = $NOW`；
   未来时间在协议上等价，但没有真机回执。验证方法：排一个 2 分钟后的开空调，
   锁屏等 2 分钟看车是否启动；失败时 App 会明确显示服务端返回的错误。
2. **小组件按钮是否路由到 App 进程**。这和控制中心是同一个风险点
   （扩展里那份 `perform()` 是空的）。如果点了没反应，说明系统把 Intent
   交给了扩展 —— 那时要么把 `QuickControlIntent.swift` 从扩展 target 摘掉，
   要么改成 `openAppWhenRun`。
3. **通知在后台能否投递**。App 被系统挂起后仍可能收到 BLE 断开回调
   （`bluetooth-central` 后台模式），但不确定；若发现后台不响、前台正常，
   说明需要再加一个"回到前台时补发"的兜底。

## 九、定时任务已移除（2026-11-05 12:12）

用户判断"没啥用"，整块删除：

- 删除文件：`Sources/UI/ScheduleView.swift`、`Sources/Support/ScheduledCommandStore.swift`、

  并在注释里保留"为什么不做云端定时"的结论（抓包无法证明 `scheduledTime` 是计划时刻，

剩下的 `操作历史` 与 `未锁提醒` 不受影响。
